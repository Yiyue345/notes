## 3. 开卷部分必须覆盖的内容

### 3.1 模块一：设计部分

你需要在当天公布的业务场景基础上完成：

```text
需求分析文档：说明核心业务、实体、属性，内容不超过2页。
E-R图：核心实体不少于5个，标清属性、主键、外键和联系基数。
关系模式转换：标明主键、外键、非空、唯一等约束。
```

最容易失分的点：

```text
只有表名，没有说明业务流程。
E-R图没有标联系的1:1、1:N、M:N。
多对多联系没有转换为中间关系表。
关系模式只写字段，遗漏主键、外键、NOT NULL、UNIQUE等约束。
```

### 3.2 模块二：SQL部分

必须使用 MySQL 或 openGauss 完成可运行代码，并提交源码与运行截图。要求包括：

| 类型 | 要求 | 分值 |
| --- | --- | ---: |
| DDL | 创建数据库、创建不少于3张表，覆盖实体完整性、参照完整性、自定义完整性 | 6 |
| DML | 选一个表使用AI辅助生成3条插入数据；自定义并实现更新、删除要求 | 6 |
| 查询 | 自定义5组涉及2张及以上表的查询，涉及 `LIKE`、`IN`、`JOIN`、`GROUP BY` 等 | 5 |
| 视图 | 创建1个用于简化高频复杂查询的视图 | 3 |

这里最重要的一句话是：

```text
代码必须自己调试运行，截图中的错误如果保留，需要分析可能原因。
```

### 3.3 模块三：事务与故障恢复

必须分析三类故障：

```text
事务故障
系统故障
介质故障
```

并为自己的业务系统设计：

```text
日常备份策略
故障发生后的恢复步骤
日志文件如何用于UNDO和REDO
```

### 3.4 模块四：数据库安全

必须完成：

```text
根据业务角色设计用户与权限体系
使用DCL实现用户创建、授权、回收权限、角色分配
从访问控制、密码安全、非法访问防范、数据泄漏防护等角度写安全策略
```

## 6. 开卷现场执行顺序

拿到当天业务背景后，建议按下面顺序做，不容易乱。

### 第一步：圈出业务对象和动作

从题目中找名词和动词：

```text
名词通常可能成为实体：用户、商品、订单、课程、预约、设备……
动词通常说明联系：购买、预约、选课、借阅、审核、支付……
```

### 第二步：确定至少5个核心实体

为每个实体列出：

```text
主键
必要属性
可能的唯一属性
和其他实体的联系
```

### 第三步：先画E-R图，再写关系模式

不要直接写SQL后再倒推图。先把业务关系想清楚，SQL表结构会稳定很多。

### 第四步：建立表并插入最小测试数据

每张关键表先准备几行可以连接起来的数据，保证后续查询、视图和截图能得到结果。

### 第五步：完成五类查询与视图

把查询要求先用中文写出来，再写SQL。例如：

```text
查询名称中包含某关键字的商品及其所属分类。
统计每位用户完成订单的总金额，只显示总金额超过指定值的用户。
```

### 第六步：补事务恢复与安全设计

这两部分不依赖大量数据，按系统角色和重要数据说明即可，但必须写得与当天业务一致。

## 7. 提交前检查清单

### 报告内容

- [ ] 需求分析不超过2页，且与当天业务背景一致。
- [ ] E-R图包含不少于5个核心实体。
- [ ] E-R图中主键、联系和联系基数标注清楚。
- [ ] 关系模式注明主键、外键、非空、唯一等约束。
- [ ] DDL至少创建3张表，并体现三类完整性。
- [ ] 插入、更新、删除均有代码和运行证据。
- [ ] 5组查询均涉及2张及以上表。
- [ ] 查询中覆盖 `LIKE`、`IN`、`JOIN`、`GROUP BY` 等要求。
- [ ] 创建了1个视图，并能查询出结果。
- [ ] 写出了三类故障及对应恢复方案。
- [ ] 写出了角色权限、DCL代码和安全策略。

### 代码与原创规范

- [ ] SQL代码已经在所选数据库中实际运行。
- [ ] 截图清楚展示SQL与结果，不能只贴代码。
- [ ] 若出现错误截图，报告中说明错误原因和修改过程。
- [ ] AI辅助生成内容经过本人修改、验证，并在报告中按要求标记。
- [ ] 不直接复制粘贴未验证的AI内容。

### 格式与提交

- [ ] 报告正文按要求使用小四字号、20磅行间距。
- [ ] 在提交截止时间前上传到正确的头歌图文作业位置。

## 8. 复习优先级建议

如果时间有限，可以按这个优先级复习：

```text
第一优先：关系代数、规范化理论
原因：闭卷，必须靠自己写出来。

第二优先：E-R图到关系表的转换、DDL和多表查询
原因：开卷分值最大，并且需要现场可运行。

第三优先：事务恢复和DCL安全代码模板
原因：题型稳定，提前整理后现场只需换业务名称。
```

开卷资料越容易检索越好；闭卷部分则要用题目反复练到不看笔记也能完成。
